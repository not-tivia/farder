✨ What Farder is

Servers, channels and roles like Discord. Self-hosted like TeamSpeak. End-to-end encryption like Signal. Owned by whoever runs it, like IRC. One program, no subscription, no terms of service.

🔑

Your identity is a key

An Ed25519 keypair, generated on your machine and encrypted at rest behind a PIN. No email, no phone number, nothing to verify and nothing to leak. A 24-word phrase brings it back if you lose the device.

🏠

Servers you actually own

A Farder server is a program on your computer — a spare laptop, a mini PC under the desk, a $5 VPS. It holds your community's data because you decided it should, and it answers to nobody else.

🌐

Relays hide the addresses

Put a server behind a relay and members never learn each other's IP — or the host's. The relay only forwards packets; it never stores your history. You choose per server, and the app tells you plainly which kind you are joining.

💬

Encrypted direct messages

DMs are sealed between the two devices with X25519 and AES-256-GCM. The server stores ciphertext it has no key for, and neither the host nor the relay can read a word.

📂

The bits you expect

Text channels, categories, roles and permissions. Voice with push-to-talk, screen sharing, replies, reactions, polls, giveaways, events and reminders. Familiar on purpose.

🖥

Retro on purpose

Tahoma. Luna Blue. Raised buttons and a real title bar. Computing was more honest when the window told you what it was, and none of this costs a gram of privacy.

🔒 Encrypted channels

A normal channel trusts the server with its contents. An encrypted channel does not. Messages are sealed on the sender's machine with MLS group encryption — the same family of cryptography behind modern secure messengers — and the server stores ciphertext it cannot open, search or hand over.

What the server holds for an encrypted channel
The text of your messages cannot read
Files you attach — sealed before they leave your machine, stored under a meaningless name cannot read
Voice messages, sealed the same way as any other file cannot read
The real filename and file type — they travel inside the encryption cannot read
Who is in the channel, and when they posted can see
How many attachments a message has, and roughly how big can see

Forward secrecy is bounded by how often a channel refreshes its keys, not absolute — and a member who joins today cannot read what was said yesterday. That is the trade an encrypted channel makes, and the app says so when you create one.

🎨 Make it yours

The client is themeable down to the colour of a button, and themes are plain CSS files you can copy and edit. Don't take our word for it — this page is running the client's own themes. Pick one and watch the site repaint.

Your choice is remembered on this device only — it is stored in your browser and sent nowhere. In the client, themes go further: every colour is a variable, and a new theme is one file in a folder.

📋 What Farder doesn't do

Every privacy product has a boundary. Most of them put it in a footnote. Here is ours, in the same size type as the good news.

Normal channels are readable by the server. Only encrypted channels are sealed. A normal channel is stored as text so that search, bots, polls and webhooks can work — and whoever runs that server can read it. Pick per channel, knowing which you picked.
A relay currently sees normal-channel traffic. It hides IP addresses, which is its job, but today it also carries normal channels in the clear between client and server. Encrypted channels, DMs and voice stay sealed from it. An inner tunnel that closes this is designed and not yet built.
Metadata leaks, as it does everywhere. Who is in a channel, when they post, and roughly how much they send are visible to the server even when the contents are not. Encryption hides what you said, never that you said something.
It is early software. Desktop only, no independent audit, and moving quickly. It is built in the open so you can check the claims on this page against the code that makes them.
