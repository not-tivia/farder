## Mesh (the "server survives the owner's PC being off" goal), status

Plan and reasoning: `docs/mesh-hosting-status.md`. Built so far:

1. **`FetchLog`** (owner or an allowed replica): pages the signed history. Owner-only on purpose: the raw log holds every
   channel's messages, including ones a member cannot open.
2. **Replicas + verified snapshots + `farder-replica`** (`crates/farder-replica`): the owner allows a member as a replica; the
   replica pulls the server's DATABASE in pieces, checks SHA-256 + SQLite integrity + that the signed history inside replays and is
   the server it asked, and keeps `latest.db` / `previous.db`. Why the database and not the log: channels, roles and categories are
   NOT in the signed log, so a log-only copy would lose them. **A replica sees everything the host sees** (private channels, invite codes).
3. **`farder-server --read-only`**: serves a copy (history, members; refuses every write with "saved copy" text; refuses newcomers;
   SQLite `query_only` as the hard guarantee). Tested with a real copy: same history id, history readable, writes refused, every table
   row unchanged afterwards (`cargo test -p farder-replica`).
4. **Client failover** (Rust compiles; **NOT yet verified end to end**): saved server gets `fallbacks` (backup addresses, this device
   only); `connect_server` tries the host first (5 s when backups exist) then the backups, keeping the connection under the host's
   address; while on a backup a probe asks the host every 20 s and closes the backup connection when the host answers so the normal
   reconnect returns. UI: "Backup copy" tab (addresses; owner can tick who keeps a copy) and a "reading a saved copy" banner.

## How to run things (and the traps)

- **Windows copy for the tests:** worktree `C:\Users\Deez\farder-selftest` (= `/mnt/c/Users/Deez/farder-selftest`). Update it:
  `cd /mnt/c/Users/Deez/farder-selftest && git checkout -q -- . ; git fetch -q /home/deez/farder features-skins-notify-garble && git checkout -q --detach FETCH_HEAD`.
  Build it (about 5 minutes): `powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'C:\Users\Deez\farder-selftest\scripts\selftest\build-windows.ps1'`.
  Needed after any client (Rust or front-end) change; not needed for server-only changes (the suites use the WSL server binary:
  `cargo build -p farder-server`).
- **Browser guest page:** build the WebAssembly with `bash scripts/build_guest_web.sh` (one-time: `rustup target add wasm32-unknown-unknown`,
  `cargo install wasm-bindgen-cli --version 0.2.117 --locked`; output `website/guest/pkg` is not committed). The suites need Edge on Windows
  and `playwright-core` in `scripts/selftest/node_modules` of the Windows copy.
- **Traps that already bit:** never `pkill -f <name>` (it matches and kills its own shell; use `pkill -x`). Never rebuild the Windows
  copy while a suite runs. Scripted edits of CRLF files (`main.rs`, `lib.rs`, `tauri-bridge.ts`, `server.rs` in protocol, `handlers.rs`,
  `connection.rs`, `commands.rs`, several `.tsx`) must preserve CRLF; the pattern used all session is read bytes, normalise to `\n`, edit,
  write back with `\r\n`. Protocol enums are positional: **append** new variants at the end only. Every new Tauri command needs an entry in
  `docs/modules/tauri-commands.md` (the doc audit fails otherwise) and a UI path (the reachability audit). No non-ASCII in Dart files
  (HealthTracker, unrelated). Memory use: tsc + cargo + two Windows apps + Edge together is heavy; the machine ran low.
- **The stack was shut down at the end of this session** (no farder-server, gateway or replica running). Suites start what they need.

## Honest gaps and caveats (so nothing is rediscovered)

- A guest-link guest cannot use voice, encrypted channels, uploads or DMs; the gateway can read normal-channel text (the page says so).
- The brake limits the RATE of damage; it does not undo anything and is not the cancellable waiting-period design (not built).
- The takeover pop-up is an in-app toast, not an operating-system notification.
- The reset message has no dedicated screen; it shows wherever the app shows a refused request.
- Deleting a channel that does not exist counts as success in the handler (so it uses a little brake budget).
- Guest page on a phone browser: only responsive CSS, never tried. Caddy: never run.
- Attachments are not copied by replicas yet; a read-only copy therefore shows messages but not their files.
- Client failover is compiled and unit-reasoned, not exercised against a killed host yet.
