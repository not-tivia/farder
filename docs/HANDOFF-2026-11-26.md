## Bugs found and fixed today

- **A read-only copy renamed the server in friends' apps** ("My Farder Server"): the name only came from `--name`. Now saved in
  `server_settings`; a copy and any later start without `--name` use it. Test in `cargo test -p farder-replica` (proven to fail
  without the fix).
- **`farder-replica` could not use the link the app gives out** (`https://farder.xyz/join/<base64>`): `--invite` now takes that,
  `farder://host:port/CODE` or a bare code; the address in the link replaces `--server`.
- **The copy machine showed as "Anonymous"** in everyone's member list: it now names itself (`--name`, default "Backup copy").
- **Owner could not tell which member is the copy machine** in Backup copy: each row shows the short key the replica prints.
- **Banners covered the channel name and the first message** (recovery + saved copy): they now sit in the chat flow under the
  header (`.chat-notices`, all six themes).

## Encrypted channel

Was "UNVERIFIED: GUI path unseen". The new suite found three real bugs, all fixed and re-run:

1. **The friend never got the first message** in a new encrypted channel: B only published its key package when it OPENED the channel,
   so A's first message was sealed before B was in the group. Now every member publishes as soon as the channel appears
   (`server:channel_created_v2` in `useServerEvents.ts`, same guards as the steward). The creator is safe because process/publish
   run under the same device-chain lock as create (checked in `run_e2ee`).
2. **A message that arrived before the reader's Welcome was cached as "couldn't decrypt" forever** (reason "no MLS group for
   channel"; nothing had been opened). `decrypt_sealed_message` now answers `not_ready`; `useSealedDecrypt` does not cache it and
   opens the row again when the channel's `mlsStates` changes.
3. **A message sealed before you were added looked like tampering** (red "couldn't decrypt" + "1 message could not be verified").
   `farder-mls` now reads the header epoch and says `BEFORE_JOINED`; the app shows "Sent before you could read this channel", not red,
   not counted. Unit test in `farder-mls` (also checks a tampered current-epoch message is NOT relabelled).

A test bug first hid all this: the composer placeholder in encrypted channels is "Encrypted message...", not "Type a message".
`ubuntu-suite.sh e2ee` runs a diagnosis scenario (`e2ee-diag`: screens, leaves, MLS state, owner add with skip reasons) on failure.
