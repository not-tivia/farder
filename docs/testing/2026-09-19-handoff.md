## 7. Asked for, not built

- **Custom typing verbs** ("chris is meowing…"). Discussed, not started. The
  open design question: in an **encrypted** channel a custom verb would be
  server-visible text attached to a member, which leaks in a place people will
  not expect. Recommendation was either to disable custom verbs there, or make
  the verb per-viewer (rendered by the reader's client, never sent).
- **Partial fetch / range requests** for plaintext files, and **chunked
  sealing** for encrypted ones. These are the next rungs after the accept gate,
  and they are what would make "stream it" and "download it" genuinely different
  operations rather than the same bytes with a different button. Chunked sealing
  is the harder half: a sealed file is currently one AEAD blob, so it cannot be
  played until it is entirely fetched and decrypted.
- **A pre-approved UGC marketplace** for profile effects on farder.xyz, so
  creators can be paid. Design constraint already settled: effects must stay
  ID-only, and a community pack must be fetched **at install time**, never at
  view time — otherwise opening someone's profile becomes a request to a server
  that learns who looked.
